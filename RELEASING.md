# Как выпускать обновления всех приложений

Гайд для того, кто правит код и выпускает новые версии. Рассчитан и на человека
(кнопки на github.com), и на Клода (те же действия через GitHub-инструменты).

Репозиторий-дом: **`WalkieWalkie/Walkie_Walkie`**. Все релизы, теги и манифесты
обновлений живут здесь. Приложения проверяют релизы этого репозитория и обновляются сами.

Действующих приложений четыре, у каждого свой независимый канал обновлений:

| Приложение | Где код | Как обновляется | Канал / имя выпуска |
|---|---|---|---|
| **Рация (Android)** | `android/` + `radio-walkie/web/` | сама качает APK из релизов | `Walkie-1.0.N.apk`, тег `walkie-v1.0.N` |
| **Радиостанция (Android)** | `radio-air/` | сама качает APK из релизов | `Station-1.0.N.apk`, тег `station-v1.0.N` |
| **Радио (ПК, станция+рация)** | `radio-air-PC/` | electron-updater, `latest.yml` | релиз `v0.X.Y`, «latest» |
| **Рация (ПК, отдельный виджет)** | `radio-air-PC/` (`pack_walkie.py`) | electron-updater, `walkie.yml` | релиз `v0.X.Y-walkie.0`, pre-release |

> **Главное правило совместимости обновлений:** новый выпуск приложение поставит поверх
> старого, только если у выпуска **больше номер версии** и (для Android) **та же подпись**.
> Понизить версию нельзя — телефон/ПК просто не предложит.

---

## Шаг 0 (один раз для нового репозитория): перецелить обновления на этот реп

Приложения ищут обновления по адресу, **зашитому в код**. При переезде на новый
репозиторий этот адрес надо поменять в 4 местах — иначе новые сборки будут отправлять
пользователей на старый репозиторий. Заменить `BuninSil/Walkie-Walkie` →
`WalkieWalkie/Walkie_Walkie` (для ПК — раздельно owner/repo):

1. `radio-air-PC/desktop/package.json` → блок `build.publish`:
   `"owner": "WalkieWalkie"`, `"repo": "Walkie_Walkie"`.
2. `radio-air-PC/pack_walkie.py` → строка с `publish` (там же owner/repo).
3. `android/app/src/main/java/ru/radio/walkie/Updater.java` → константы `RELEASES`, `FEED`, `DOWNLOAD`.
4. `radio-air/app/src/main/java/ru/radio/station/Updater.java` → те же три константы.

Проверить, что нигде не осталось старого адреса:
`grep -rn "BuninSil/Walkie-Walkie" .` — должно быть пусто (кроме, может, истории/README).

> Это делается **один раз**. Дальше про адрес можно забыть.

### Важно при переезде: не сбрасывать номера версий

Автонумерация Android (кнопка «Выпустить релиз») берёт **последний релиз в этом же
репозитории +1**. В новом репе релизов ещё нет — поэтому первый выпуск посчитается «с нуля»
(1.0.1) и окажется **ниже** уже установленных версий, и обновление не встанет.

Первые релизы в новом репе нужно выпустить с номерами **выше мостовых** (мостовые выпущены
в старом репе):

| Приложение | Мостовая версия (старый реп) | Первый релиз в новом репе — не ниже |
|---|---|---|
| Рация (Android) | 1.0.84 | **1.0.85** |
| Радиостанция (Android) | 1.0.32 | **1.0.33** |
| Радио (ПК) | 0.3.0 | **0.3.1** |
| Рация (ПК) | 0.3.0-walkie.0 | **0.3.1-walkie.0** |

- **ПК:** просто ставишь нужную версию в `package.json` руками — проблема не возникает.
- **Android:** если кнопка предлагает номер ниже таблицы — задай его вручную. Проще всего собрать
  и подписать первый выпуск локально с нужным `WALKIE_BUILD_NUMBER` (см. «Запасной путь» ниже),
  либо один раз временно создать в новом репе релиз-заглушку с тегом `walkie-v1.0.84` /
  `station-v1.0.32`, чтобы кнопка дальше считала от него.

Дальше номера растут сами, про это можно забыть.

## Шаг 1 (один раз): владелец добавляет ключ подписи Android в секреты

Нужно только для **Android**-приложений (ПК-подпись не требует секретов). Делает владелец
организации. Ключ в репозиторий **не кладётся никогда** — реп публичный, с ключом кто угодно
выпустит «обновление» на чужие телефоны.

1. Реп → **Settings → Secrets and variables → Actions → New repository secret**.
2. Добавить два секрета (значения — в файле `WALKIE-SECRETS.txt`, полученном вместе с ключом):
   - `WALKIE_KEYSTORE_PASSWORD` — пароль ключа;
   - `WALKIE_KEYSTORE_BASE64` — ключ `walkie-release.p12` в base64, **одной строкой целиком**.
     Сделать заново: Linux/macOS `base64 -w0 walkie-release.p12`;
     Windows PowerShell `[Convert]::ToBase64String([IO.File]::ReadAllBytes("walkie-release.p12"))`.
3. Дать соавторам доступ: **Settings → Collaborators** (или роли организации) → роль **Write**.
4. Для Клода-соавтора: на репе должно стоять GitHub-приложение **Claude**
   (https://github.com/apps/claude/installations/select_target → организация → этот реп).

Отпечаток «того самого» ключа: `E7:DD:C0:8B…C7:3B:2` (полный SHA256
`e7ddc08b94fe2d00dfbf49262e2fdaa5d085801bd2da8e8f4209c473512c73b2`). Сборка сверяет его сама.

> Храните `walkie-release.p12` и пароль ещё и у себя (облако/флешка). Потеряете ключ —
> выпускать обновления поверх установленных Android-приложений будет нечем, только переустановка.

## Шаг 2: внести изменения в код

| Что меняем | Где |
|---|---|
| Рация Android: обёртка (уведомление, кнопка поверх, экран блокировки, обновления) | `android/app/src/main/java/ru/radio/walkie/` |
| Рация Android: настройки ⚙, внешний вид 🎨, «Что нового» | `android/app/src/main/assets/android/` |
| Рация Android: сама рация (экран, кнопки, звук, эфир) | `radio-walkie/web/` — Gradle копирует её в APK (`copyWalkieWeb`); «Радио» и «Рация» на ПК её **не** используют |
| Станция Android: логика эфира, плейлист, декодер | `radio-air/app/src/main/java/ru/radio/station/` |
| Станция Android: интерфейс | `radio-air/app/src/main/assets/ui/` |
| ПК «Радио» и «Рация»: окна, рация-виджет, эфир, сервер | `radio-air-PC/` (`js/`, `desktop/`, `css/`) |

> ⚠️ У рации две копии кода: `radio-walkie/web/js/` (Android) и `radio-air-PC/js/` (ПК).
> `codec.js`, `crypto.js`, `link.js` сейчас совпадают байт в байт, `widget.js`, `live.js`,
> `engine.js`, `stations.js` — разошлись. Правку протокола эфира (`live.js`, `codec.js`,
> `crypto.js`, формат пакетов) вноси **в обе копии**, а заодно сверяй
> `radio-air-PC/desktop/codec-node.js` (ретрансляция интернет-радио) и
> `radio-air/…/AirPacket.java` (станция Android) — иначе ПК, телефоны и станция перестанут
> слышать друг друга. Такие правки проверяй на ПК и на телефоне одновременно.

После каждого пуша в Android-код GitHub собирает проверочную сборку (Actions). Зелёная
галочка = код собирается. Это **не** релизы, пользователи их не видят. «Радио» и «Рация» на
пуш не собираются — для проверки запусти «PC apps (Радио + Рация)» без галочки публикации.

## Шаг 3А: выпуск Android (Рация / Радиостанция)

Одна кнопка, версия считается сама.

1. **Обновить «Что нового» в коде** (плашка в приложении, работает без интернета):
   - Рация: `android/app/src/main/assets/android/changelog.js` — новая запись **сверху**:
     `{ ver: '1.0.N', items: [ { level: 0, text: '**Заголовок.** Описание.' } ] },`
   - Станция: `radio-air/app/src/main/assets/ui/app.js` (массив `WALKIE_CHANGELOG`), так же.
   - `N` = последний выпущенный номер этого приложения + 1. Запушить.
2. Реп → **Actions** → **«Выпустить релиз»** → **Run workflow**:
   - **Use workflow from**: `main`;
   - **Что выпускаем**: `walkie` или `station`;
   - **Что нового**: пункты через `;` (это текст релиза на GitHub).
3. **Run workflow**. Через 4–6 минут в **Releases** появится `Рация 1.0.N` / `Радиостанция 1.0.N` с APK.

Кнопка сама: берёт последний номер +1, собирает release-APK, подписывает ключом из секретов
(с проверкой отпечатка), пишет текст релиза, публикует. Телефоны подхватят при следующем входе
или в течение 6 часов в фоне. Вручную: рация → ⚙ → «Обновления» → «Проверить»; станция → блок
«Обновления» внизу.

**Клоду:** шаг 2 — через `actions_run_trigger` (`run_workflow`, `workflow_id: publish.yml`,
`inputs: { app, changes }`); шаг 1 — через `push_files`.

## Шаг 3Б: выпуск ПК (Радио — станция, и Рация — виджет)

У ПК номер версии берётся из файла, поэтому его **поднимают вручную перед выпуском**.

1. **Поднять версию** в `radio-air-PC/desktop/package.json` и
   `radio-air-PC/desktop/package-lock.json` (поля `version`, в lock — три места):
   было `0.2.9` → стало, например, `0.3.0`.
2. **Обновить «Что нового»**: `radio-air-PC/js/changelog.js` — запись `{ ver: '0.3.0', … }` **сверху**.
   Верхняя запись = текущая версия, по ней плашка понимает, что нового.
3. Запушить пункты 1–2.
4. Реп → **Actions** → **«PC apps (Радио + Рация)»** → **Run workflow**:
   - **Что релизить**: `both` (обе), `station` (только «Радио») или `walkie` (только виджет «Рация»);
   - **Опубликовать релиз**: галочку **включить** (без неё — только проверочная сборка).
5. **Run workflow**. Через ~4 минуты появятся релизы:
   - «Радио» → `v0.3.0` (обычный, latest) + `latest.yml` + `Radio-Setup-0.3.0.exe`;
   - «Рация» → `v0.3.0-walkie.0` (pre-release) + `walkie.yml`.

Установленные ПК-приложения проверяют обновление при запуске и раз в час. Вручную — кнопка
«Проверить» в ⚙ → «Обновления».

**Про два трека ПК:** «Радио» (станция) сидит на обычных релизах (`latest.yml`), «Рация»-виджет —
на своём канале `walkie` (pre-release релизы `-walkie.0`, см. `allowPrerelease` в `main.js`).
Поэтому Android-релизы в этом же репе **не должны быть `--latest`** (иначе перебьют трек станции) —
воркфлоу это уже соблюдает.

**Клоду:** `actions_run_trigger` (`run_workflow`, `workflow_id: pc-release.yml`,
`inputs: { target, publish: "true" }`); версии/чейнджлог — `push_files`.

## Правила версий (коротко)

- **Android**: номер один — `1.0.N`, только растёт, +1 к последнему **этого же** приложения.
  Рация и станция считаются раздельно.
- **ПК**: semver `0.X.Y` в `package.json`. Тег станции `v0.X.Y`, тег виджета `v0.X.Y-walkie.0`.
- Никогда не понижай и не переиспользуй номер: и Android, и electron-updater игнорируют
  версию не выше установленной.

## Если сборка красная

Открыть упавший запуск (Actions) → упавший шаг → текст ошибки.

| Ошибка | Что делать |
|---|---|
| «нет секретов WALKIE_KEYSTORE_BASE64 / PASSWORD» | не сделан шаг 1 (только для Android) |
| «не тот ключ подписи» / отпечаток не совпал | в секрете другой ключ или base64 обрезан — вставить заново одной строкой |
| `keytool … password was incorrect` | неверный `WALKIE_KEYSTORE_PASSWORD` |
| `error:` в `.java` / сборке | ошибка в коде — исправить, запушить, запустить снова |
| Нет кнопки **Run workflow** | нет прав Write, или Claude-приложение не стоит на репе, или workflow смотрит не в `main` |
| ПК: «не удалось проверить» обновление | в репе появился Android-релиз с `--latest` и перебил `latest.yml` станции — Android-релизы должны быть не-latest |

Упавший выпуск ничего не публикует. Android-номер не «сгорает» — следующий запуск возьмёт тот же `N`.

## Удалить неудачный релиз

Проще выпустить следующий с исправлением (номер больше — обновятся на него). Удалить руками:
**Releases → релиз → Delete**, затем **Tags → тот же тег → Delete**. Кто успел поставить,
останется на своей версии до следующего выпуска.

---

## Проверить обновление вживую

1. Стоит старая версия (Android: ⚙ → «Обновления» / низ экрана станции; ПК: ⚙ → «Обновления»).
2. Выпустить новую (шаг 3А/3Б).
3. Android: закрыть-открыть приложение → «Доступно 1.0.N» → загрузка (первый раз попросит
   «разрешить установку из этого источника»). ПК: перезапустить → проверка при старте.
4. После установки — плашка «Что нового» с твоими пунктами.

Рация не ставит обновление во время передачи, станция — во время эфира; ПК-станция — не в эфире.

## Запасной путь: собрать и подписать Android у себя

Если Actions недоступны. Нужен ключ `walkie-release.p12` и пароль.

1. **JDK 17+** и Android SDK. `N` = последний выпуск + 1:
   ```bash
   export WALKIE_KEYSTORE_FILE=/путь/walkie-release.p12
   export WALKIE_KEYSTORE_PASSWORD='пароль'
   export WALKIE_BUILD_NUMBER=N
   cd android            # или radio-air для станции
   ./gradlew assembleRelease
   ```
   APK: `app/build/outputs/apk/release/app-release.apk` → переименовать в `Walkie-1.0.N.apk` / `Station-1.0.N.apk`.
2. Если собрался неподписанным: `python android/tools/sign_v2.py app-release-unsigned.apk Walkie-1.0.N.apk walkie-release.p12 ПАРОЛЬ` (нужен `pip install cryptography`).
3. **Releases → Draft a new release**: тег `walkie-v1.0.N` (рация) / `station-v1.0.N` (станция),
   заголовок `Рация 1.0.N` / `Радиостанция 1.0.N`, текст с `## Новое в 1.0.N`, APK файлом, **Publish**.
   Для Android-релизов **снять** галку «Set as latest release» (чтобы не перебить ПК-трек).

ПК собирается через `radio-air-PC` (electron-builder) и обычно выпускается только воркфлоу —
локально сборка установщика требует Windows и не нужна для штатных релизов.
